CASE STUDY / LLM SECURITY EVALUATION

Test the boundary.
Record the behavior.

Structured evaluation of instruction hierarchy, tool authorization, data boundaries, secret handling and consequential-action confirmation.

IN PLAIN LANGUAGE

What does an AI security evaluation do?

It checks whether an AI assistant follows important rules when a user, a document or a tool gives it conflicting instructions. This project defines repeatable test situations, records how a model responds and checks whether its behavior matches the expected security rule.

01

Set the rule

For example, an assistant must not reveal a secret or approve an action without permission.

02

Test the conflict

Give the model controlled instructions that challenge the rule and inspect its response.

03

Score the result

Use a defined rubric to record whether the behavior passed, failed or needs more evidence.

01 / OBJECTIVE

Evaluation question

When a model receives conflicting instructions or security-relevant requests, does it respect instruction hierarchy, tool authorization, data boundaries, secret-handling requirements and consequential-action confirmation?

02 / COVERAGE

12 controlled scenarios

Direct and indirect prompt injection, instruction hierarchy, tool authorization, tool-output injection, data exfiltration, secret handling, policy evasion, refusal calibration, data boundaries and consequential-action confirmation.

03 / PRELIMINARY EXECUTION

Two seven-case runs

The project README records 14 case-level runs on 8 November 2026 using dynamic public free-model routing and synthetic tools. Two vulnerable-profile cases resulted in simulated privileged tool acceptance; tested hardened-profile cases made no privileged refund/export call.

04 / INTERPRETATION

Observed harness behavior, not a real-world exploit

All tools were local synthetic functions. No real refund, CRM export, payment or customer-data disclosure occurred. Dynamic model routing prevents a stable model-to-model comparison; two trials per scenario are insufficient for a statistically reliable attack-success estimate.

05 / LIMITATIONS & NEXT EVIDENCE

What remains unproven

The full raw provider-response export is not committed, independent human adjudication is not recorded, and the 120-row repeated-trial ledger remains planned rather than executed. The project does not claim a production penetration test or paid red-team engagement.
